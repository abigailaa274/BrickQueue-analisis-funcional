# Ciclo de vida de un ticket de bug/mejora
**Propietario:** Abigail Arias
**Ultima actualización:** 14 de sep. de 2026
**Scope:** El proceso cubre el ciclo completo de un ticket de bug o mejora en BrickQueue: detección, creación, asignación, notificaciones, resolución, cierre, validación por el solicitante y reapertura cuando la resolución no es satisfactoria.

# Flujo de gestión y resolución de tickets
## Información del diagrama
Este diagrama representa el proceso de creación, asignación, resolución y validación de tickets por bugs o mejoras. Participan el Developer solicitante, el PM, el Developer resolutor y el sistema de notificaciones. Si la resolución no es satisfactoria, el ticket se reabre y vuelve a asignarse; si es satisfactoria, el proceso finaliza.

## SOP para la gestión y resolución de tickets
1. Detectar un bug o identificar una mejora.
2. Crear un ticket con la información correspondiente.
3. Solicitar al PM la asignación de uno o más resolutores.
4. Asignar el ticket al Developer resolutor.
5. Enviar la notificación de asignación.
6. Avanzar el ticket al estado «En progreso».
7. Resolver el problema o implementar la mejora.
8. Cerrar el ticket.
9. Enviar la notificación de cierre.
10. Evaluar si la resolución es satisfactoria.
	10.1. Si la resolución es satisfactoria, marcar el ticket como «Resuelto satisfactoriamente».
	10.2. Finalizar el proceso.
	10.3. Si la resolución no es satisfactoria, reabrir el ticket.
	10.4. Volver a asignar el ticket a uno o más resolutores.
	10.5. Repetir el ciclo de notificación, resolución, cierre y validación.
11. Considerar que la reapertura también puede ser realizada por el Developer resolutor o el PM.
